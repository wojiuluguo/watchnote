# 腕记 4.1.x 版本说明与插件 API 定稿

> 状态：**4.1.34 / versionCode 143**（插件模块 0.4.5：**布局容器树 `UIPage`** + **元素画布 / 整页画布（同一套 `Pen`）** + **联网渠道 `host.net()`** + **插件主页面 / 指示栏第 6 格**；`API_LEVEL` 4→5、`MODULE_VERSION` 0.4→0.4.5。这一版不叫 0.5：插件改腕记官方页面还没做。release APK 已构建、校验、归档）
> 这份文档解决两件事：①4.1.x 这一整条线对外怎么说、发布前还要做什么；②插件 API 到插件模块 0.4.5（4.1.34）为止到底定成什么样（含前置模块与 SHAPE 形状行；一页看全，不用翻两个设计文档）。
> 相关文档：`插件模块-API设计.md`（为什么这么设计、每个细节的取舍）、`插件外置化-v2设计.md`（.wplugin 包格式与加载流程）、`插件作者手册.md`（写插件的人看）。

## 一、对外更新说明（可直接贴商店）

4.1.x 这一条线本质是「把 App 拆成宿主 + 插件」的地基改造，**大部分用户看不出界面变化**；能看见的只有插件入口和几个内置示例插件。所以对外说明不要吹「插件系统」，按实际看得见的东西写：

```
4.1.16
1. 设置：新增「插件」管理页，可以开关内置插件
2. 设置：插件页顶部新增「插件页面」入口，所有插件页面一列直达
3. 插件：支持安装外置插件包（.wplugin），可预览、卸载
4. 插件：安装前显示清单（名字、版本、作者、权限、大小、指纹）
5. 插件：连续出错 3 次自动停用，不影响主程序
6. 插件：可用系统文件选择器选包安装
7. 插件：内置「笔记统计」「笔记详情」「快捷入口」三个示例
8. 主题颜色：整页改由插件绘制，外观与 4.0.20 一致
9. 插件：外置插件包支持作者签名，安装前能看到作者指纹
10. 插件：新增「手机传 / 网址安装」，手机连同一个 Wi-Fi 就能把包传到手表
11. 插件：手表能直接按网址下载插件包，不用手机传文件
12. 插件：修复插件页左下角小按钮和大返回键挤在一起的问题
```

规则仍是「一条一件事、位置一起头」。发布时**只留用户真能看到的行**：第 3~6 条如果不想把插件包功能暴露给所有人，可以删掉，只留 1、2、7、8。

4.1.17 只修了自测项，没有用户可见的新功能，**不新增对外条目**；真要上 4.1.17，商店文案直接沿用上面这段，只把开头版本号改成 4.1.17。

4.1.18 只修外置插件的安装链路，界面不变。对外只需加一条（或并进上面那段）：

```
插件：修复外置插件安装时报「插件加载失败」
插件：手机传包后文件名不再乱码
```

4.1.19 只加内部诊断日志和一条自测项，界面没有任何变化，**不新增对外条目**；真要上 4.1.19，商店文案沿用上面这段，只把版本号改掉。

4.1.20 修的是「外置插件（含手机传包）在真机上装不上」，界面无变化，对外文案加一条即可：

```
插件：修复外置插件安装失败的问题
```

4.1.21 让**外置插件也能带页面**（以前只有内置插件画得出页面）。对外可加一条：

```
插件：外置插件现在也能带页面
```

4.1.22 修「示例页面插件里点『计数加一』，页面上的数字不跟着变」（toast 数到 10、页面还是 0），
同时给页面 API 补上「按最新数据重画」。对外可加一条：

```
插件：修复示例页面里点按钮后数字不刷新
```

4.1.23–4.1.33 的用户可见变化见 `版本历史.md` 对应行。0.4.5（4.1.34）对外文案：

```
插件：插件页面能自己排布局（横排/竖排/分组/网格/滚动）
插件：插件页面能自己画图形（环形图、仪表盘、整页表盘）
插件：插件可以联网（走腕记这一条通道，设置里能关）
插件：插件可以有自己的整页，指示栏多一格
插件：内置「画布演示」，装上就能看布局与画布的效果
```

### 3.2 五条硬规则（改 API 前先读）

1. **能加就能收**：插件加的每个页面/按钮都记在插件名下，卸载按 id 一键全删；关插件（disable）只收走页面/按钮、保留 kv，真卸载才清数据。
2. **外壳归宿主，内容两轨**：插件既可用官方组件（声明式行）与容器树自动排，也可在元素画布/整页画布上自绘（0.4.5 起）；但页面外壳——标题、返回键、圆屏安全区、滚动、崩溃隔离——永远由宿主给，插件画不到外壳以外。风格统一靠官方组件兜底，上限靠画布打开，两者同层混用。
3. **只加不改**：API 只能加方法/加默认参数，不能改已有语义；加能力就升 `PluginApi.API_LEVEL`；改语义也算破坏性变更；淘汰先 Deprecated 留一个大版本。
4. **崩溃隔离**：插件按钮/页面/事件回调全包 `runCatching`，连续 3 次出错自动停用该插件（kv 保留、管理页留原因），主程序不闪退。
5. **配额上限**：每插件最多 3 页；同一插件在每个插槽最多 2 个按钮；PAGE_BOTTOM / CARD_ACTION 全局各 2 个；设置页整页 4 行（官方 2 + 第三方 2）；页面 id 必须带 `插件id:` 前缀；超了返回 `Rejected` 而不是崩溃。

### 3.3 还没开放

- **写接口**：`WRITE_NOTES` 权限已定义但未实现，插件只能只读笔记。
- **网络**：0.4.5 起开放，但只有宿主一条渠道 `host.net()`（见 §3.5）；插件不能自己起 socket、不能传文件。
- **后台/通知**：插件不能起 Service、不能发通知。
- **设置页正文 / 编辑页 / 备份恢复**：不在 HostScreen 白名单里。
- **签名证书链 / 作者身份认证**：签名只有自签公钥指纹（4.1.14 起可选），没有第三方背书；插件商店也还没有。
- **自由画布 / 任意 Compose**：0.4.5 起开放两级画布（元素画布、整页画布），但仍是宿主提供的画笔 API，不是让插件直接写 `@Composable`。自己写 `PageSpec.content` 那种 @Composable 页面仍然只有打进宿主的内置插件能做——外置插件是独立编译的 dex，需要 Compose 编译器，而且宿主 R8 会裁掉没被引用到的 Compose UI 组件，风险不可控。
- 插件没有数据库、没有跨插件通信、不能起后台服务；网络只能走 `host.net()`。

### 3.4 加一个新插件要改哪里

- **内置插件**：只改 `plugin/BuiltinPlugins.kt` 的 `all` 加一行（id / name / summary / build / defaultEnabled），安装、开关、管理页、页面入口全自动。现有五个：主题颜色（默认开）、笔记统计（默认开）、笔记详情（默认关）、快捷入口（默认关）、画布演示（默认关，0.4.5）。
- **外置插件**：写好 `plugin.json` + dex，打包成 `.wplugin`，用管理页三个入口之一安装（示例包 / plugins-inbox 文件夹 / 系统文件选择器），全程先预览再确认。

### 3.5 0.4.5 开放了什么（4.1.34 起，现行契约）

| 能力 | 入口 | 约束 |
|---|---|---|
| 布局容器树 | `UIPage.column/row/box/group/grid/scroll/spacer/divider` | 树深 ≤16、节点 ≤200、成环拒绝；`weight/height/pad/spacing/columns/align/action/onTap/onDrag` |
| 元素画布 | `Ui.canvas(heightDp) { pen -> }` | 单帧 ≤4000 指令、`onDraw` 超 8ms 连续 3 次降为静态帧、绘制异常只丢这一块 |
| 整页画布 | `Ui.fillCanvas {}` + `page.fullPage()` | 外壳仍由宿主给（安全区、返回、崩溃/超时隔离），标题可不要 |
| 联网 | `host.net().get/post/request` | 只 http(s)、禁本机/内网、响应 ≤256KB、超时 5~30s、30 次/分、并发 2、离开页面取消；权限 `Permission.NET` |
| 插件主页面 | 清单 `mainPage: { title }` → `asMainPage()` | 每插件最多 1 页；指示栏 5→6 格，≥2 个插件页时第 6 格是抽屉 |

**混用规则（没有 mode 开关）**：官方行、容器、元素画布、整页画布、第三方插件组件同层混排；宿主 API 与第三方插件 API 在页面任何位置都能调，包括画布回调里（回调不阻塞，请求回来 `host.invalidate()` 下一帧重画）。谁也没被禁用。

**为什么是 0.4.5 不是 0.5**：0.5 的硬要求是「插件能改腕记官方页面的布置与按钮样式」。这一版只开放插件自己的页面，官方页面结构仍未做成可注入，所以版本号停在 0.4.5；关于页与插件页底部已写明这条原因。

写插件的具体代码示例见 `插件作者手册.md` 第十节。
