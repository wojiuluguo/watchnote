## 一、对外更新说明（可直接贴商店）

4.1.x 这一条线本质是「把 App 拆成宿主 + 插件」的地基改造，**大部分用户看不出界面变化**；能看见的只有插件入口和几个内置示例插件。所以对外说明不要吹「插件系统」，按实际看得见的东西写：

```
4.1.16
1. 设置：新增「插件」管理页，可以开关内置插件
2. 设置：插件页顶部新增「插件页面」入口，所有插件页面一列直达
3. 插件：支持安装外置插件包（.wplugin），可预览、卸载
4. 插件：安装前显示清单（名字、版本、作者、权限、大小、指纹）
5. 插件：连续出错 3 次自动停用，不影响主程序
6. 插件：可用系统文件选择器选包安装
7. 插件：内置「笔记统计」「笔记详情」「快捷入口」三个示例
8. 主题颜色：整页改由插件绘制，外观与 4.0.20 一致
9. 插件：外置插件包支持作者签名，安装前能看到作者指纹
10. 插件：新增「手机传 / 网址安装」，手机连同一个 Wi-Fi 就能把包传到手表
11. 插件：手表能直接按网址下载插件包，不用手机传文件
12. 插件：修复插件页左下角小按钮和大返回键挤在一起的问题
```

规则仍是「一条一件事、位置一起头」。发布时**只留用户真能看到的行**：第 3~6 条如果不想把插件包功能暴露给所有人，可以删掉，只留 1、2、7、8。

4.1.17 只修了自测项，没有用户可见的新功能，**不新增对外条目**；真要上 4.1.17，商店文案直接沿用上面这段，只把开头版本号改成 4.1.17。

4.1.18 只修外置插件的安装链路，界面不变。对外只需加一条（或并进上面那段）：

```
插件：修复外置插件安装时报「插件加载失败」
插件：手机传包后文件名不再乱码
```

4.1.19 只加内部诊断日志和一条自测项，界面没有任何变化，**不新增对外条目**；真要上 4.1.19，商店文案沿用上面这段，只把版本号改掉。

4.1.20 修的是「外置插件（含手机传包）在真机上装不上」，界面无变化，对外文案加一条即可：

```
插件：修复外置插件安装失败的问题
```

4.1.21 让**外置插件也能带页面**（以前只有内置插件画得出页面）。对外可加一条：

```
插件：外置插件现在也能带页面
```

4.1.22 修「示例页面插件里点『计数加一』，页面上的数字不跟着变」（toast 数到 10、页面还是 0），
同时给页面 API 补上「按最新数据重画」。对外可加一条：

```
插件：修复示例页面里点按钮后数字不刷新
```

## 三、插件 API 定稿（4.1.16）

### 3.1 一页清单

**插件本体**

| API | 形态 | 起于 |
|---|---|---|
| `PluginApi.API_LEVEL` | `const val = 2`，宿主 API 版本（0.2 起，4.1.27 升） | 4.1.0 |
| `PluginApi.MODULE_VERSION` | `const val = "0.2"`，插件模块版本（0.x 测试阶段；关于→详细信息里显示） | 4.1.23 |
| `PluginManifest(id, name, version, minApi = API_LEVEL, permissions = emptySet())` | data class | 4.1.0 |
| `Permission` | enum：READ_NOTES / WRITE_NOTES（未开放能力）/ READ_SETTINGS | 4.1.0 |
| `WristPlugin` | 接口：`manifest` / `install(host)` / `uninstall()` | 4.1.0 |
| `PluginHost` | 宿主交给插件的手柄（见下） | 4.1.0 |

**宿主手柄 PluginHost**

| 成员 | 作用 | 起于 |
|---|---|---|
| `pages: PageRegistry` | add(PageSpec) / add(ListPageSpec) / remove(pageId) / removeAll() / all() | 4.1.0（列表页 4.1.7） |
| `buttons: ButtonRegistry` | add(ButtonSpec) / remove(id) / removeAll() | 4.1.1 |
| `data: DataApi` | notes() / tags() / kv() | 4.1.0（kv 落盘 4.1.3） |
| `events: EventBus` | onNoteSaved(listener) / onPageShown(listener)，返回取消订阅函数 | 4.1.0 |

### 3.2 五条硬规则（改 API 前先读）

1. **能加就能收**：插件加的每个页面/按钮都记在插件名下，卸载按 id 一键全删；关插件（disable）只收走页面/按钮、保留 kv，真卸载才清数据。
2. **不给自由画布**：插件只能用官方插槽 + 官方组件，不能自己画外壳——否则每个插件风格不一样，圆屏和安全区兜不住。
3. **只加不改**：API 只能加方法/加默认参数，不能改已有语义；加能力就升 `PluginApi.API_LEVEL`；改语义也算破坏性变更；淘汰先 Deprecated 留一个大版本。
4. **崩溃隔离**：插件按钮/页面/事件回调全包 `runCatching`，连续 3 次出错自动停用该插件（kv 保留、管理页留原因），主程序不闪退。
5. **配额上限**：每插件最多 3 页、每个按钮插槽最多 2 个按钮；页面 id 必须带 `插件id:` 前缀；超了返回 `Rejected` 而不是崩溃。

### 3.3 还没开放

- **写接口**：`WRITE_NOTES` 权限已定义但未实现，插件只能只读笔记。
- **网络**：外置插件没有网络能力，v2 明确不带网络。
- **后台/通知**：插件不能起 Service、不能发通知。
- **设置页正文 / 编辑页 / 备份恢复**：不在 HostScreen 白名单里。
- **签名证书链 / 作者身份认证**：签名只有自签公钥指纹（4.1.14 起可选），没有第三方背书；插件商店也还没有。
- **自由画布的页面**：4.1.21 起外置插件可以带页面了，但只能走 `SimplePage`（声明式：统计行/按钮行 + 回调，宿主渲染）。自己写 `PageSpec.content` 那种 @Composable 页面仍然只有打进宿主的内置插件能做——外置插件是独立编译的 dex，需要 Compose 编译器，而且宿主 R8 会裁掉没被引用到的 Compose UI 组件，风险不可控。
- 插件没有网络、没有数据库、没有跨插件通信。

### 3.4 加一个新插件要改哪里

- **内置插件**：只改 `plugin/BuiltinPlugins.kt` 的 `all` 加一行（id / name / summary / build / defaultEnabled），安装、开关、管理页、页面入口全自动。现有四个：主题颜色（默认开）、笔记统计（默认开）、笔记详情（默认关）、快捷入口（默认关）。
- **外置插件**：写好 `plugin.json` + dex，打包成 `.wplugin`，用管理页三个入口之一安装（示例包 / plugins-inbox 文件夹 / 系统文件选择器），全程先预览再确认。
