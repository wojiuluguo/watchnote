# 最终版施工计划（一点一点往上搭）

> 背景：3.0 开始"全部重写"是问题根源——把 2.5 里已经完整的官方组件（AppScaffold/ScreenScaffold/TransformingLazyColumn/EdgeButton/TimeText/Fish）丢掉了，之后 3.1~3.8 一直在补丁上打补丁，所以出现"改了没变化、返回没了、动画没了、按钮没绑定"。

## 总原则（必须遵守）

1. **不在一版里塞所有需求**：按下面的步骤一步一步搭，每步只做一件事；
2. **每步先验收再下一步**：每步完成后给出验收清单，通过才继续；
3. **一个步骤只打一次包**，不在每次改动后打包；
4. **底子用 2.5 架构**（官方组件齐全），不要再用 3.x 的自造架构；
5. 3.x 里被用户认可的东西（见《版本历史.md》"优秀点清单"）**逐条搬入**，不重写。

## 步骤规划（v4.x）

### Step 0 · 底子（v4.0.0）
- 用 v2.5 结构搭空壳：AppScaffold + ScreenScaffold + TransformingLazyColumn + EdgeButton + TimeText + Fish + SafeRotaryBehavior；
- 4 个空页面能左右滑动，底部 EdgeButton 有出现/消失动画；
- 释放包（release），体积 < 2MB。
- **验收**：能滑、按钮会从底部滑入/滑到底滑出、表冠能滚、不崩。

### Step 1 · 笔记（v4.1.0）
- 笔记列表、新建/编辑/删除、标签输入、★标记/✓完成、语音转文字、录音/播放；
- 数据存 SharedPreferences。
- **验收**：新建→编辑→删除→重启 App 数据都在；录音可放；标签能自己输。

### Step 2 · 课程表（v4.2.0）
- 星期切换、时段卡片、进行中高亮/剩余分钟；
- 添加/编辑/删除时段（名称、类型、起止时间、重复星期）；恢复默认时间表。
- **验收**：改一个时段保存后立刻刷新；7 天显示正确；跨天不崩。

### Step 3 · 时间页（v4.3.0）
- 整屏圆环（按 480×480 表盘，直径 ≈ 表盘 95%~100%）；
- 内容严格按用户图纸（不多加任何东西）：
  1. 该阶段名称
  2. 同一行：本段几点到几点（左） | 现在几点（右）
  3. 剩余时间（大字，配"分钟后结束/分钟后开始"）
  4. 下一个阶段名称
  5. 下一个阶段几点到几点
  - 圆环 = 进度条，整屏贴边；
  - 不加百分比、不加页点、不加顶部时间、不加其它提示文字。
- 半秒同步；算法：剩余 = 结束−现在；空闲 = 下一段开始−现在；跨天显示"空闲到明天 HH:mm"；
- 时间页隐藏顶部时间。
- **验收**：7:52 在 07:30–08:00 显示 8 分钟；晚上显示"空闲到明天"；圆环明显贴边。

### Step 4 · 设置与返回（v4.4.0）
- 设置整页列表：时间表管理、恢复默认、导出/恢复备份、更换主题颜色、动画效果、清空、关于；
- 子页统一：官方 ScreenScaffold 槽位里的返回 EdgeButton「←」；设置页「↩」回笔记页；
- 系统返回：子页→上一层；普通页→上一页；笔记页→退出确认。
- **验收**：每个子页都能用按钮返回；短页面（关于）返回按钮也在；不会卡死。

### Step 5 · 动画与主题（v4.5.0）
- 满血模式：Fish 鱼眼（官方 TransformingLazyColumn）、子页滑入、圆环动画、页点动画、EdgeButton 动画；
- 性能模式：只保留翻页 + EdgeButton，其余关闭；
- 主题色 5 套 + 持久化。
- **验收**：切换模式立即生效；滚动笔记/课程表鱼眼明显；主题色重启后保留。

### Step 6 · 收尾（v4.9.0）
- 崩溃日志（复制 + 下载）、备份导入导出验证、体积、文档、无用代码清理；
- 最终候选，用户验收后升 v5.0.0。

## 版本号规则
- v4.0.0 底子 → v4.1.0 笔记 → v4.2.0 课程表 → v4.3.0 时间页 → v4.4.0 设置 → v4.5.0 动画 → v4.9.0 候选 → v5.0.0 最终。
- 每步 versionCode 递增，覆盖安装。

## 打包规则
- 每完成一个 Step、验收清单自检通过，才打一次 release 包；
- 中间调试不打包；
- 包名固定 `com.ioo.watchnote`，统一 debug keystore 签名；
- APK 放 `版本档案/` 对应子目录，最新版放根目录。

## 验收模板（每次给用户）
```
Step N 完成
本步做了什么：...
请测试：1) ... 2) ... 3) ...
已知未做：...
```
## 五、用户确认（最新）

- **标准版本（用户相对满意）= v3.1.0**：四个页面 + 返回按钮 + release 流畅；缺点是圆环偏小、时间页空闲算法旧。
- **最终版 = 以 v3.1.0 为基线重新搭**，功能与当前版本（v3.8.4）一致，一次性把各版本优秀点搬入。
- 页面定义（A/B/C/D）：
  - **A 笔记**：笔记列表、新建/编辑/删除、标签输入、★标记/✓完成、语音转文字、录音/播放。
  - **B 课程表**：星期切换、时段卡片（进行中高亮+剩余分钟）、添加/编辑/删除时段、恢复默认时间表。
  - **C 剩余时间**：整屏圆环 + 阶段名/本段起止/现在几点/剩余大字/下一段名/下一段起止；半秒同步；跨天正确处理。
  - **D 设置**：时间表管理、恢复默认、导出/恢复备份、更换主题颜色、动画效果（满血/性能）、清空数据、关于。
- 返回规则：每个子页面底部「←」返回；设置页底部「↩」回笔记页；系统返回=上一层/上一页/根页面退出确认。
- 打包规则：按 Step 完成验收后只打一次 release 包。

> 注：v3.1.0 是 release 混淆包，反编译看不到组件名（R8 改名）；以用户实际体验为准，作为 UI/交互基线。
## 六、版本同步规则（用户反馈）

- **用户导包到手表慢，实际安装版本通常比开发最新版落后 1 个包**，所以：
  1. 用户反馈“没变化”时，先核对关于页/设置页显示的**实际安装版本**；
  2. 每次交付必须写清楚“这一版包含什么、对比的是哪一版”；
  3. 关于页与设置页必须显示真实 versionName / versionCode（不许写死）；
  4. 不频繁打包，每个 Step 只打一次，避免用户追版本。

## 七、设计原则（教训）

- **不要自作聪明改用户没要求的东西**；
- 需要避让/腾位置时，**优先隐藏**，不要缩小、不要删功能（例：顶部时间和圆环重叠时，应该隐藏顶部时间，而不是把圆环缩小）；
- 任何“优化”都要在交付说明里单独列出，让用户确认。
