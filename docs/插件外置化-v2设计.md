# 插件外置化（v2）设计

状态：方案已定；4.1.9 起有「清单契约 + 校验器」，4.1.10 起 v2.0 加载器已完成，4.1.11 起有安装前清单确认与降级拒绝，4.1.12 起页面有统一入口，4.1.13 起有系统文件选择器安装（无文件选择器的手表会提示改用文件夹安装），4.1.14 起可校验作者签名（ECDSA P-256，公钥指纹进安装预览、安装记录和插件详情），4.1.15 起有「手机传 / 网址安装」两条自助通道（`PluginReceiverServer`：手表开局域网网页收上传，或由手表自己按直链下载）
（包结构检查 → 解压 → DexClassLoader → 安装记录 / 启动恢复 / 卸载，内置示例插件可一键验证）。
目标读者：以后写外置插件的人、以及接手这个模块的人。

## 一、要解决什么

现在所有插件都必须编译进 App（`BuiltinPlugins.all` 一行一个）。要让「插件非常多」，就必须能装外置插件：
用户拿到一个 `.wplugin` 包 → 宿主校验 → 出现在插件管理页 → 打开/关闭/卸载和内置插件完全一样。

- 目标：不重新发版就能加插件；外置和内置走同一套 `PluginCore`；插件出问题不影响宿主；权限在安装时看得见。
- 非目标：v2.0 不做在线商店、不做插件联网、不做自动升级、不做跨插件通信。

## 二、技术路线对比

| 路线 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 动态 dex（`.wplugin` 里放 `classes.dex`，`DexClassLoader` 加载） | 插件就是编译好的 `WristPlugin`，和内置插件一套 API、一套 UI；体积小；宿主改动最少 | 作者要会用 Kotlin/Java 编译 dex，门槛比脚本高 | **选它** |
| 外部 APK 插件（解析 APK 的 classloader + 资源） | 能带图标/图片资源；可以独立签名 | 要处理 PackageManager 解析、签名校验、资源 id 冲突、外部 Activity 与圆屏 UI 的冲突 | v2.0 不做，留 v2.2 再评估 |
| JS 脚本（Rhino/QuickJS 里跑） | 门槛低，改一行就能试 | 等于再做一套脚本版 API 绑定，两套 API 长期维护；圆屏 UI、鱼眼列表用脚本写很别扭 | 不选 |
| WebView H5 页面 | 生态成熟 | 和「原生圆屏、鱼眼列表、表冠滚动」完全格格不入；性能与体验断档 | 不选 |

选动态 dex 的核心理由：**API 不分裂**。插件作者写的就是 `WristPlugin`、`PageSpec`、`Official`，
宿主里面也不用为「脚本插件」再维护一套适配层——插件多起来以后，唯一撑得住的是「只有一套 API」。

## 三、包格式（.wplugin 就是 zip）

```
hello.wplugin
├─ plugin.json          清单（必需）
├─ classes.dex          编译产物（必需；可再加 classes2.dex、classes3.dex…）
└─ assets/              插件自带资源（可选，v2.0 只允许读，不注入宿主资源表）
```

`plugin.json` 字段（校验规则已在 `ExternalPluginManifestParser` 里实现，4.1.9 起）：

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `schemaVersion` | 是 | 目前只认 `1` |
| `id` | 是 | 反向域名，小写字母/数字/下划线，至少两段，≤64 字符；禁止 `com.ioo.watchnote` 前缀（内置插件保留） |
| `name` | 是 | 显示名，≤24 字符 |
| `version` | 是 | ≥1 的整数，升级要更大 |
| `minApi` | 否 | 默认等于宿主当前 API；大于宿主 `API_LEVEL` 直接拒绝 |
| `entryClass` | 是 | 完整类名，必须实现 `WristPlugin` |
| `permissions` | 否 | 字符串数组，只能是已知枚举（`READ_NOTES` / `WRITE_NOTES` / `READ_SETTINGS`） |
| `author` | 否 | ≤40 字符 |
| `description` | 否 | ≤200 字符 |
| `kind` | 否 | `app`（默认）或 `lib`；`lib` 是前置模块：不占界面，只通过 `provides` 对外提供类（4.1.29 起） |
| `provides` | 否 | 仅 `lib` 可写：完整类名数组，≤16 个、每个 ≤128 字符；宿主逐个查重，官方已占用的类名单独标 blocked |
| `requires` | 否 | 依赖数组，每项 `"id"` 或 `"id>=版本"`，≤8 个；缺前置或版本低时只有依赖者装不上（4.1.29 起） |

示例：

```json
{
  "schemaVersion": 1,
  "id": "com.example.hello",
  "name": "你好插件",
  "version": 1,
  "minApi": 1,
  "entryClass": "com.example.hello.HelloPlugin",
  "permissions": ["READ_NOTES"],
  "author": "示例作者",
  "description": "一个最小外置插件"
}
```

## 四、信任与安全

- 安装必须是**用户显式动作**：用户在文件选择器里选 `.wplugin` → 宿主先显示清单预览（名字、作者、权限）→ 用户点安装。不做静默安装、不做后台自动更新。
- 宿主记录安装包的 SHA-256 写进安装记录，卸载时一起清；管理页显示这个指纹，用户能对上「我装的是不是那个包」。
- v2.0 插件拿不到网络：外置插件目录里不放任何网络相关能力，`DataApi` 也没有网络接口；拿不到网络，笔记就传不出去。
- 写权限继续不开（`WRITE_NOTES` 枚举先留着，v2.0 校验器认它，但 `DataApi` 里没有写接口——申请了也用不了，文档写清楚）。
- 插件代码和宿主同进程，所以**不做进程级沙箱**（圆屏 UI 跨进程画不了）：隔离靠 `PluginCore` 的 `runCatching` + 以后加「连续 3 次失败自动停用」+ 安装失败整体回滚。
- 作者签名（4.1.14 起，v2.2）：包可以带签名，装了签名版以后不能被「换钥匙」或「没签名的包」覆盖。签名是**可选**的——第一次装没签名的包仍然允许（没有分发中心时，装机信任就是用户自己选的包），但升级路径受保护。
- 签名不证明「这人可信」，只证明「这个包和当初签名的是同一个包，而且没换作者钥匙」。真正的信任要靠分发渠道和作者口碑。

### 签名格式 v1（4.1.14 起）

- 包内多一个文件：`plugin.sig`（Base64 文本，≤4096 字符），内容是 ECDSA P-256 / SHA-256 的 DER 签名。
- 公钥放在 `plugin.json` 的 `publicKey`（Base64 的 X.509 SubjectPublicKeyInfo），算法字段 `signingAlgorithm` 固定 `SHA256withECDSA`。
- 签名原文（UTF-8，行尾 LF）＝第一行固定 `WRISTNOTE-PLUGIN-SIGNATURE-V1`，之后每个非 `plugin.sig` 文件一行：
  `<sha256 小写 hex> <字节数> <包内路径>`，按路径的 UTF-8 字节序升序（逐字节无符号比较，不是区域排序）。
- 目录条目不算文件：宿主读 zip 时会跳过 `entry.isDirectory`，作者工具也必须跳过 `assets/` 这类目录条目；条目路径统一用 `/`，反斜杠先归一化。
- 公钥指纹＝SHA-256(SPKI) 前 16 个 hex 大写；安装预览、外置插件详情、安装记录都显示它，用户可以对上「是不是同一个作者」。
- 校验时机：解压前（`ExternalPackageChecker.inspect`）就算摘要并验签，签名不对直接拒装，不落地；升级时再比一次指纹。
- 作者侧签名工具：`docs/external-sample/sign-sample.ps1`（第一次 `-NewKey` 生成密钥，之后直接签；会把公钥写回 `plugin.json` 并重打包）。
- 该脚本与宿主做过跨语言对照验证：PowerShell/.NET 签出的包由 Node crypto 独立验签通过（含 `assets/` 目录条目和中文/emoji 文件名）。`docs/external-sample/hello-signed.wplugin` 是签好的示例包（指纹 `E1B6E3610EE9F811`），可直接用来验安装预览里的「已签名」显示；示例私钥不随仓库提供。

## 五、加载流程（4.1.10 已实现）

1. 用户选中 `.wplugin` → 解压前先校验 zip 条目路径（拒绝 `../` 逃逸、拒绝绝对路径、拒绝符号链接）。
2. 读 `plugin.json` → `ExternalPluginManifestParser.parseFile` 校验。
3. 解压到私有目录 `filesDir/plugins/<id>/<version>/`，算 SHA-256。
4. 建 `DexClassLoader(dexDir, optimizedDirectory = codeCacheDir, libraryPath = null, parent = 宿主 classLoader)`。
5. `Class.forName(entryClass, true, loader)` → 断言实现 `WristPlugin` → `newInstance()`。
6. `PluginCore.install(plugin)`：成功才落盘安装记录（清单 + 目录 + SHA-256 + 开关）；失败删目录、回滚。
7. 卸载：`PluginCore.uninstall` → 删目录 → 删 kv 文件 → 删记录。
8. 升级：新包 `version` 必须更大；先解压到临时目录 → 安装成功后再删旧目录（失败保留旧版可用）。

4.1.10 的实现与上面有这几处差异（以代码为准）：

- 包检查在 `ExternalPluginPackage.kt`（`object ExternalPackageChecker.inspect`）：先验路径 / 条目数 / 大小 / 必备文件，通过后才解压，绝不把没验过的条目写盘。
- 解压目录是 `filesDir/plugins/<id>/<version>/`，DexClassLoader 的 dex 路径直接用包内文件的绝对路径，code cache 用 `codeCacheDir/plugin-dex/<id>/`。
- 安装记录存 SharedPreferences `watchnote_external_plugins`（JSON 数组：id / name / version / entryClass / author / sha256 / installedAt / fileName），启动时 `restoreAll()` 按记录恢复。
- 同 id 重装：先 `disable` 旧版（保留 kv）再装新包；「新版本号必须更大」的校验还没做（v2.1 补）。
- 安装入口目前只有「＋ 安装示例插件」和「⇩ 从文件夹安装」（`getExternalFilesDir(null)/plugins-inbox`），还没有系统文件选择器。
- 加载失败/目录被删：`restoreAll()` 删掉这条记录并跳过，不影响其它插件。

## 六、失败模式（任何一条都不能让宿主起不来）

| 情况 | 宿主行为 |
| --- | --- |
| 清单不合法 | 拒绝安装，显示校验器的中文原因 |
| dex 损坏 / 类找不到 / 没实现 WristPlugin | 安装失败，提示「插件包损坏或入口类不对」 |
| 插件 `minApi` 高于宿主 | 拒绝，提示「需要更新的腕记」 |
| `install()` 抛异常 | `PluginCore` 已有回滚，插件状态不变 |
| 运行中按钮/页面/事件抛异常 | 4.1.11 起累计失败：连续 3 次自动停用该插件（页面按钮收走、kv 保留、管理页留原因） |
| 安装目录被手动删 | 下次启动标记「缺失」，管理页可一键清理 |
| 宿主启动时安装失败 | 跳过这一个插件、记录日志，其它插件照装 |

## 七、版本协商

- 宿主能力提升就升 `PluginApi.API_LEVEL`（只加不改，见 `插件模块-API设计.md` 的「API 变更纪律」）。
- 插件用 `minApi` 声明最低要求；清单校验（4.1.9 已实现）先拒一次，加载器装之前再检查一次（防清单被改）。
- 向后兼容：v2 宿主能装 v1 契约插件；v3 宿主能装 v1/v2 契约插件——清单只加字段、不删字段。

## 九、不做什么（省得以后反复拉扯）

- 不做任意 shell / 文件系统访问；插件只能碰 `DataApi` 和自己的 `kv`。
- 不做后台常驻 / 定时任务。
- 不做插件之间互相调用（v2 不开放跨插件通信）。
- 不做动态皮肤注入（主题颜色插件还是走内置那条路）。
- 不做「卸载后保留插件目录」——卸载就是清干净，要保留的是 kv 里的数据（管理页关掉≠卸载，这是现有语义）。
