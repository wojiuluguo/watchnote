# 插件作者手册（4.1.14 起）

> 给「以后要写插件的人」看的：怎么加一个插件、能用什么、不能碰什么、出错会怎样。
> API 设计理由见同目录 `插件模块-API设计.md`。

## 一、最小可用插件（照着抄）

```kotlin
package com.ioo.watchnote.plugin.builtin

import com.ioo.watchnote.Store
import com.ioo.watchnote.plugin.*

class HelloPlugin(private val store: Store) : WristPlugin {

    override val manifest = PluginManifest(
        id = "com.ioo.watchnote.hello",   // 全局唯一，也是页面前缀
        name = "你好插件",
        version = 1,
        permissions = setOf(Permission.READ_NOTES),
    )

    override fun install(host: PluginHost) {
        host.pages.add(
            PageSpec(
                id = manifest.id + ":main",           // 必须带前缀
                title = "你好",
            ) { scope, _ ->
                Official.Title("你好", "来自插件的页面")
                Official.Button("↩", "点我关闭", onClick = { scope.close() })
            }
        )
        host.buttons.add(
            ButtonSpec(
                id = manifest.id + ":set",
                slot = ButtonSlot.SETTINGS_ROW,
                icon = "✎",
                label = "你好插件设置",
                onClick = { host.toast("这一行是插件加的") },
            )
        )
    }

    override fun uninstall() {
        // 可选：自己收回订阅；忘了宿主也会按 pluginId 兜底清
    }
}
```

然后只改一个地方：

```kotlin
// plugin/BuiltinPlugins.kt
BuiltinPluginEntry(
    id = HelloPlugin.PLUGIN_ID,
    name = "你好插件",
    summary = "演示用",
    build = { store, onChanged -> HelloPlugin(store) },
)
```

装进 `BuiltinPlugins.all` 就会自动出现在「设置 → 插件」里，默认开着；
安装、开关、管理页、重启恢复全都不用改代码。

**如果插件会改动主界面观感（往卡片上加按钮、往主页面加东西），必须加 `defaultEnabled = false`：**

```kotlin
BuiltinPluginEntry(
    id = NoteInfoPlugin.PLUGIN_ID,
    name = "笔记详情",
    summary = "默认关闭：每条笔记卡片上多一个 ⓘ",
    build = { store, _ -> NoteInfoPlugin(store) },
    defaultEnabled = false,   // 用户去「设置 → 插件」里手动打开才生效
)
```

不能装完就悄悄改用户天天看的界面；默认关着、用户自己开，关掉又恢复原样。

## 二、能用什么

| 能用的 | 入口 | 说明 |
| --- | --- | --- |
| 加页面 | `host.pages.add(PageSpec)` | 最多 3 页；id 必须以插件 id + 冒号开头 |
| 加列表页 | `host.pages.add(ListPageSpec)` | 条目多、要滚动的页面用这一种；配额和 id 规则同上 |
| 加声明式页面 | `host.pages.add(SimplePage)` | 不写 Compose 也能加页面（Java 外置插件走这条）；插件只交「行数据」，宿主用官方组件画（0.2 起有 17 种官方行，0.4 加 shape 共 18 种，见下面「官方 UI 行」） |
| 让页面数字跟着数据变 | `SimplePage.render(p -> ...)` | 4.1.22 起：宿主每次重画都重跑这个回调，里面读最新数据重新给行；只注册一次 stat/button 的话数字会停在装上的那一刻 |
| 删页面 | `host.pages.remove(pageId)` / `removeAll()` | 只能删自己的 |
| 加按钮 | `host.buttons.add(ButtonSpec)` | 三个插槽；同一插件在每个插槽最多 2 个；设置页整页最多 4 行（官方占 2 行 + 第三方 2 行） |
| 删按钮 | `host.buttons.remove(buttonId)` / `removeAll()` | 只能删自己的 |
| 读笔记 | `host.data.notes()` / `tags()` | 只读快照；要先申请 READ_NOTES |
| 存自己的数据 | `host.data.kv()` | 按插件隔离，已落盘，重启还在 |
| 打开自己的页面 | `host.openPage(pageId)` | 只能开本插件注册的页面，跨插件会被拒绝 |
| 往笔记卡片加动作 | `ButtonSpec(slot = CARD_ACTION, onCardAction = { note -> … })` | 必须带 onCardAction，点的是哪条笔记就收到哪条 |
| 订阅事件 | `host.events.onNoteSaved{}` / `onPageShown{}` | 返回取消订阅函数 |
| 刷新宿主 | `host.invalidate()` | 改完数据让宿主重组 |
| 提示用户 | `host.toast("…")` | 手表上一闪而过的提示 |
| 官方组件 | `Official.Page` / `Title` / `Stat` / `Button` / `Confirm` / 0.2 起的 Section / Note / Hero / Item / Progress / Ring / Stepper / Chips / ColorCard / TimeCard / Toggle / Divider / Space / Empty / Bars / 0.4 起的 Shape | 和宿主长得一模一样；声明式页面直接调 `SimplePage` 的同名行方法即可，不用自己写 Compose |
| 引用官方页面 | `host.openHostPage(HostScreen…)` / `Official.ScreenRow(host, …)` | 只能开白名单里的只读官方页，不用自己重画 |
| 页面入口（自动） | 不用调 API | 4.1.12 起管理页会列出所有插件页面并可直接打开，不用为了「能被找到」再注册按钮 |

官方组件的用法（推荐所有插件都这么写，别自己画外壳）：

```kotlin
host.pages.add(
    PageSpec(id = manifest.id + ":stats", title = "统计") { scope, _ ->
        Official.Page("统计", "共 12 条", onBack = { scope.close() }) {
            Official.Stat("全部笔记", "12")
            Official.Stat("已完成", "5")
            Official.Button("⟳", "刷新", onClick = { host.invalidate() })
        }
    }
)
// 从设置页那一行跳进来（可选）：
ButtonSpec(id = manifest.id + ":open", slot = ButtonSlot.SETTINGS_ROW,
    icon = "▤", label = "统计", onClick = { host.openPage(manifest.id + ":stats") })
```

4.1.12 起这个设置行按钮**不是必须的**：管理页顶部「插件页面」会列出所有运行中插件的页面，用户在那里也能直接点进来；
设置行只是让入口离用户更近，放不放都行。

- `Official.Page` 已经把背景、返回键、圆屏安全区、表冠滚动配好了，内容按顺序竖排，**不要再套 Column**。
- `Official.Stat` 是只读数字行，天生不可点；要能点的用 `Official.Button`。
- 完整样例见 `plugin/builtin/StatsPlugin.kt`。

### 官方 UI 行（插件模块 0.2，4.1.27 起；0.4 加 shape 共 18 种）

4.1.27 把宿主里已经在用的官方 UI 全部开成了插件 API。两套写法是同一份实现，
行类型一一对应，**Kotlin 内置插件习惯用 `Official.*`，Java 外置插件用 `SimplePage` 的链式行方法**：

| SimplePage 行方法（Java 友好） | Official 函数（Kotlin 用） | 长什么样 |
| --- | --- | --- |
| `section(text)` | `Official.Section(text)` | 小节标题（11sp 次要色，和设置页分组标题一样） |
| `note(text)` | `Official.Note(text)` | 一段说明文字 |
| `hero(label, value, sub)` | `Official.Hero(label, value, sub)` | 大号数字主指标（value 用大字号突出） |
| `stat(label, value)` | `Official.Stat(label, value)` | 只读统计行（不可点） |
| `button(symbol, label, trailing, actionId, danger)` | `Official.Button(symbol, label, trailing, danger, onClick)` | 设置风格一行按钮 |
| `item(symbol, title, sub, trailing, actionId)` | `Official.Item(symbol, title, sub, trailing, onClick)` | 两行列表行（标题 + 副标题，可点） |
| `progress(label, done, total)` | `Official.Progress(label, value, total, trailing)` | 横向进度条 + 百分比（长条） |
| `ring(label, done, total)` | `Official.Ring(label, value, total)` | 环形进度（96dp 圆环 + 中间百分比） |
| `stepper(label, value, min, max, step, actionId)` | `Official.Stepper(label, value, min, max, step, onChange)` | 数值步进：−号 / 数值 / ＋号（点一下改一步） |
| `chips(label, options, selected, actionId)` | `Official.Chips(label, options, selected, onSelect)` | 一排可选项（每行最多 4 个自动折行） |
| `colorCard(label, colorHex, trailing, active, actionId)` | `Official.ColorCard(label, colorHex, trailing, active, onClick)` | 整行彩色的颜色卡（就是主题颜色页那种卡片） |
| `timeCard(start, end, trailing, actionId)` | `Official.TimeCard(start, end, trailing, onClick)` | 时间范围卡（「X 开始 / Y 截止」） |
| `toggle(label, on, actionId)` | `Official.Toggle(label, on, onToggle)` | 开关行（右侧显示「开 / 关」） |
| `divider()` | `Official.Divider()` | 一条细分割线 |
| `space(dp)` | `Official.Space(height)` | 一段竖向空白 |
| `empty(text)` | `Official.Empty(text)` | 空状态提示 |
| `bars(label, values, trailing)` | `Official.Bars(label, values, trailing)` | 柱状图（34dp 小柱，适合「最近几次」这类数据） |
| `shape(name, label, sizeDp, colorHex, actionId)` | `Official.Shape(shape, label, size, colorHex, onClick)` | 一个小图形（triangle / star / diamond / hexagon），边长 24~120dp，颜色留空跟主题 |

**带参数的行的回调编号（0.2 定死，写进自测了，不会随版本变）**：

| 行 | 用户操作 | 插件收到的 actionId |
| --- | --- | --- |
| `chips(... actionId = "freq")` | 点第 i 个选项（从 0 数） | `"freq:i"` |
| `stepper(... actionId = "cups")` | 点 ＋ | `"cups:+1"`（step = 2 就是 `"cups:+2"`） |
| `stepper(... actionId = "cups")` | 点 − | `"cups:-1"` |
| `toggle(... actionId = "sound")` | 打开 / 关闭 | `"sound:on"` / `"sound:off"` |
| `button/item/colorCard/timeCard` | 点整行 | 原样的 actionId |
| `shape(... actionId = "badge")` | 点图形 | 原样的 actionId（不拼序号） |

Java 里就是拿到字符串自己 `startsWith / endsWith` 拆，示例见 `docs/external-sample/PagePlugin.java`：

```java
new SimplePage(id, "我的页面")
    .section("主指标")
    .hero("计数", "42", "点下面加一")
    .progress("今日进度", 3, 10)
    .stepper("杯数", 3, 0, 20, 1, "cups")
    .chips("提醒频率", "低|中|高", 1, "freq")     // 选项串用竖线分隔，比 List 好写
    .toggle("提示音", true, "sound")
    .bars("最近 5 次", "1,5,3,8,2", "峰值 8")    // 数值串用逗号分隔
    .onAction(actionId -> {
        if (actionId.startsWith("cups:")) { /* endsWith(":+1") 就是 +1 */ }
        if (actionId.startsWith("freq:")) { /* substring(5) 是选中序号 */ }
    });
```

- 这些行**全部由宿主渲染**：插件交数据、宿主画，所以圆屏边距、主题色、字号、点击反馈都跟着用户主题走，
  插件画不出别的风格（这是故意的，见「三、不能碰什么」）。
- 行方法只是往列表里追加一行，链式调用顺序就是屏幕上的顺序；
  页面超过一屏时宿主自己滚动，不用插件管。
- 新 API 每加一批能力就升一次 `PluginApi.API_LEVEL`，`plugin.json` 的 `"minApi"` 写你实际用到的
  最高一级；老宿主会**明确拒绝安装**，而不是装上去再 `NoSuchMethodError`：

| API_LEVEL | 多了什么 | 用到了就写 |
| --- | --- | --- |
| 1 | 最初的一批：页面 / 按钮 / 数据 / 事件 / `openPage`（「一、最小可用插件」那一套） | `"minApi": 1` |
| 2 | 17 种官方 UI 行（section … bars，即上面那张表） | `"minApi": 2` |
| 3 | 前置模块：`kind` / `provides` / `requires`、`host.libraries`（见「九、前置模块」） | `"minApi": 3` |
| 4 | SHAPE 形状行：第 18 种行 `shape` + `Official.Shape`（4.1.30 起） | `"minApi": 4` |

当前宿主是 **API_LEVEL 4**（插件模块 0.4）。只用到老能力的插件可以继续写小一点的 `minApi`，
这样能装进更老的宿主；用 shape 就必须写 4。


条目一多就必须用列表页（4.1.7 起），别用内容页硬塞：

```kotlin
host.pages.add(
    ListPageSpec(id = manifest.id + ":tags", title = "分类分布") { list, scope, _ ->
        list.item(key = "head") { Official.Title("分类分布", "共 12 类") }
        host.data.tags().forEach { tag ->
            list.item(key = "tag-" + tag) { Official.Stat(tag, "3") }
        }
    }
)
```

- 内容页（PageSpec）里是一个普通 Column，条目一多会一次性全量一遍；列表页（ListPageSpec）交给宿主懒加载，只画屏幕附近几行。
- 列表页一样有鱼眼缩放、圆屏边距、背景和返回键，全部由宿主负责，不要自己套 LazyColumn。
- list.item 的 key 传数据自己的 id（例如 tag 名），刷新时条目状态和滚动位置不会乱跳；条目数量已知时也可以用 list.items(count) { i -> … }。
- 两种页面共用「每插件最多 3 页」的配额，id 同样必须以插件 id + 冒号开头。

引用官方页面（4.1.8 起）

宿主已经有的页面（时间表管理、特殊时段、发到手机、插件管理、关于、自测、开源网址、动画效果）
**不要自己重画**，直接链过去就行，返回键、圆屏边距、主题色全都自动一致：

```kotlin
host.pages.add(
    PageSpec(id = manifest.id + ":home", title = "快捷入口") { scope, _ ->
        Official.Page {
            Official.ScreenRow(host, HostScreen.MANAGE, "≡")          // 时间表管理
            Official.ScreenRow(host, HostScreen.SPECIAL_LIST, "◷")    // 特殊时段
            Official.ScreenRow(host, HostScreen.SHARE_TO_PHONE, "⇪")  // 发到手机
        }
    }
)
```

- `HostScreen` 是白名单枚举：`ABOUT` / `SELF_TEST` / `OPEN_SOURCE` / `PLUGIN_MANAGER` /
  `MANAGE` / `SPECIAL_LIST` / `SHARE_TO_PHONE` / `ANIM_MODE`。
- 打开的是宿主自己那一份页面：返回键回你的插件页，不会留在官方页里出不来。
- 会改数据的页（编辑页、设置正文、备份恢复）**不在白名单里**，插件拿不到——这是故意的。
- 离了宿主单独跑（比如自测里）只会 toast「宿主导航未就绪」，不抛异常。
- 完整样板见 `plugin/builtin/ShortcutsPlugin.kt`（「快捷入口」插件，默认关闭）。

按钮插槽：

- `PAGE_BOTTOM`：插件页左下角的小圆按钮（36dp，和主页面那颗小按钮同一套尺寸）。
  位置和升降由宿主页面壳统一管：页面还需要滚动时它才出现在左下角，官方大返回键升起时它跟着飞下去
  ——别把这个位置当常驻操作栏，也别在页面内容里再放一颗同样功能的按钮。
  只有用 `Official.Page` 画壳的页面才会出现这排按钮；插件自己画的裸页没有（屏幕底部是宿主的地盘）。
  样例：`builtin/StatsPlugin.kt` 的「⟳ 刷新统计」——点一下 `host.invalidate()`，
  因为页面内容是从 `host.data.notes()` 现读的，重组后数字就更新了：
- `SETTINGS_ROW`：设置页里多出来的行
- `CARD_ACTION`：笔记卡片右侧的动作圆钮（4.1.5 起生效）。它多一个必填回调：

```kotlin
ButtonSpec(
    id = manifest.id + ":open",
    slot = ButtonSlot.CARD_ACTION,
    icon = "ⓘ",
    label = "这条笔记的详情",
    onClick = {},                              // CARD_ACTION 用不到，但要填
    onCardAction = { note ->                   // 必须写：宿主把被点的那条笔记交给你
        host.data.kv().putString("last", note.id)   // 页面参数只有 Int，要传 id 就存 kv
        host.openPage(manifest.id + ":info")
    },
)
```

没有插件注册 CARD_ACTION 时，笔记卡片上不会多任何东西，布局和以前一样。

```kotlin
ButtonSpec(
    id = manifest.id + ":refresh",
    slot = ButtonSlot.PAGE_BOTTOM,
    icon = "⟳",
    label = "刷新统计",
    onClick = { host.invalidate() },
)
```

统计页那颗刷新钮就是上面这段；页面内容每次重组都重新读数据，所以 invalidate 就够。


## 三、不能碰什么

1. 不能自己画整个页面外壳——背景、返回键、圆屏安全区、表冠滚动都是宿主的；插件只交内容。
2. 不能删/改宿主页面和数据；v1 连写笔记都不开放。
3. 拿不到 Activity、拿不到宿主导航栈，只能通过 `PageScope.open/close` 走自己的页面。
4. 不能注册没申请权限的数据接口——会直接抛异常，开发期就会暴露，不会静默给空数据。
5. 不能超过上限：每插件 3 页、每插槽 2 个按钮；超了返回 `RegisterResult.Rejected(原因)`。

## 四、数据和生命周期

- 插件私有数据 `kv`：**已落盘**（4.1.3 起，一个插件一个偏好文件，重启不丢）；
  **管理页里「关掉」不会清**，重新打开还在；
  只有真卸载（`PluginCore.uninstall()`，比如以后从系统里删插件）才清空。
- 开关状态存在 `watchnote_plugins`；插件数据一个插件一个文件：
  `watchnote_plugin_<pluginId>`。
- 管理页详情里能看到你这个插件装了哪些页面/按钮、存了哪些数据键、权限是什么，
  调试时先看那里，比加日志快。
- 插件自己状态乱了（比如缓存和宿主不同步），在管理页点「重新加载」：收走页面按钮但**不清数据**，
  等价于 `PluginCore.reload(plugin)`；真卸载才会清 kv。
- `install()` 只在插件被装上/打开时跑一次，别在这里做重活；
  页面内容才是每次显示时重组的部分。
- `install()` 抛异常 = 整体回滚，宿主状态不变，插件显示「安装失败」；
  按钮回调抛异常只弹 toast；事件监听器抛异常被吞掉。
- **4.1.11 起有熔断**：按钮 / 卡片按钮 / 事件回调连续抛 3 次，宿主会自动停用你的插件
  （页面和按钮收走、私有 kv 保留），失败原因写在管理页详情里；成功跑一次或重新安装就清零。
  所以别把「一定会抛」的路径写进按钮回调，调试期自己先 try/catch 打日志。

## 五、常见错误对照

| 现象 | 原因 |
| --- | --- |
| 安装返回 Rejected「页面 id 必须用插件 id 加冒号开头」 | PageSpec.id 没带 `<pluginId>:` |
| Rejected「每个插件最多 3 页」 | 注册超过 3 页 |
| Rejected「插槽 PAGE_BOTTOM 已满」 | 该插槽已有 2 个按钮 |
| Rejected「CARD_ACTION 按钮必须提供 onCardAction…」 | 卡片按钮没写 onCardAction（只给了 onClick） |
| Rejected「只有 CARD_ACTION 按钮能带 onCardAction」 | 其它插槽多写了 onCardAction |
| Rejected「需要宿主 API N，当前只有 …」 | manifest.minApi 比宿主高 |
| 页面显示空白 | content 里没画东西，或页面已被删（宿主会自动退回上一层） |
| toast「插件不能打开别的插件的页面」 | `host.openPage` 传了别人插件的 pageId |
| toast「插件页面不存在：…」 | pageId 拼错，或该页面还没注册 |
| toast「宿主导航未就绪」 | 当前宿主没接官方页面导航（只会在自测/裸 PluginCore 里出现） |
| 调 notes() 抛「没有申请 READ_NOTES 权限」 | permissions 里没写 |

## 六、还没支持的（别踩空）

- 外置插件：4.1.10 起可以真装了（zip/dex 动态加载已通），见 `插件外置化-v2设计.md` 与下面「八、外置插件怎么装」。
  4.1.21 起 Java 写的外置插件也能**带页面**：用 `SimplePage`（声明式，插件只交行数据，宿主渲染），
  4.1.22 起再加 `SimplePage.render(...)` 让行按最新数据重画；
  4.1.27（插件模块 0.2）起 `SimplePage` 有 17 种官方行，4.1.30（0.4）加上 shape 共 18 种（见「官方 UI 行」），外置插件也能用整套官方 UI；
  样例见 `docs/external-sample/PagePlugin.java`。
- 自己写 `@Composable` 页面（`PageSpec` / `ListPageSpec`）：仍然只有打进宿主的内置插件能做；外置插件独立编译，需要 Compose 编译器，且宿主 R8 会裁掉没被引用到的 Compose UI 组件，不开放。
- 写笔记 / 写设置：只读，写接口等权限模型稳定再开。
- 插件自己开后台服务 / 定时任务：没有这个能力，别规划成后台插件。
- 卡片动作的其它位置：v1 只接在「笔记」卡片上，办事/倒计时等卡片还没接。
- 官方页面只能开白名单里的只读页；编辑页/设置正文/备份恢复没有开放，要改数据请用按钮 + 官方组件自己拼。


## 七、API 会变吗（写插件前先看这条）

会变，但按规矩变：**只加不改**。

- 已经发布的名字（页面/按钮/数据/事件/Official 组件）不改、不删、不换参数顺序；
  新能力用新增字段（带默认值）或新增函数的方式加。
- 加新能力会升 `PluginApi.API_LEVEL`；插件在 `manifest.minApi` 里声明自己要哪级，
  宿主装不下会返回明确原因，不会静默不生效。
- 语义变化也算破坏：同一个回调从主线程挪到后台、调用时机改变，都会升 API_LEVEL。
- 要被淘汰的 API 会先标 Deprecated、文档写替代写法，至少留一个大版本再删。
- 内置插件目录有健康检查（自测第 17 项）：id 重复、manifest.id 对不上、超页数/按钮数上限，
  自测页立刻变红——所以加内置插件时忘了改一处，装上之前就能发现。

## 八、外置插件怎么装（v2，4.1.10 起）

插件可以不编译进 App，而是打成一个 `.wplugin`（就是 zip）；装进手表后和内置插件一样出现在管理页，一样开关、一样卸载。

包结构：

```
hello.wplugin
├─ plugin.json
├─ classes.dex     ← 你的插件编译出来的 dex（可以再带 classes2.dex…）
└─ assets/         ← 可选；v2.0 只保留文件，还不注入宿主资源表
```

`plugin.json` 可以照这个抄：

```json
{
  "schemaVersion": 1,
  "id": "com.example.hello",
  "name": "你好插件",
  "version": 1,
  "minApi": 1,
  "entryClass": "com.example.hello.HelloPlugin",
  "permissions": ["READ_NOTES"],
  "author": "你的名字",
  "description": "一句话介绍"
}
```

- `id` 必须是反向域名，小写字母/数字/下划线，至少两段；不能用 `com.ioo.watchnote` 开头（内置插件保留）。
- `entryClass` 指向实现 `WristPlugin` 的类；写法和内置插件完全一样（`manifest` + `install` + `uninstall`）。
- `permissions` 只能写已知的三种；`minApi` 别超过宿主版本，否则直接被拒。
- 清单校验器会给中文原因，不抛异常：`ExternalPluginManifestParser.parseFile(file)`。

包体限制（超了整包拒绝，不会只装一半）：

- 包体 ≤ 4 MB；条目 ≤ 128 个；解压后总大小 ≤ 16 MB；单个文件 ≤ 8 MB；`plugin.json` ≤ 64 KB。
- 只允许 `plugin.json`、`classes*.dex`、`assets/…` 三类文件，出现别的文件整包拒绝。
- 路径越界（`../`、绝对路径、含冒号）直接拒；同名条目直接拒。

写法和编译：

- Java 或 Kotlin 都行。4.1.21 起 Java 写的外置插件也能带页面，用声明式 `SimplePage`（插件只交行数据 + 一个 action 回调 + 4.1.22 起的重画回调，宿主用官方组件画），不需要 Compose 编译器；4.1.27（插件模块 0.2）起行类型扩到 17 种官方 UI，用法见上面「官方 UI 行」。
- 自由画布的页面（`PageSpec` / `ListPageSpec`，`content` 是 `@Composable`）仍然只有打进宿主的内置插件能做——外置插件独立编译，Java 写不了 Compose，宿主 R8 也会裁掉没被引用到的 Compose UI 组件。**0.4.5 起外置插件也能画**：走宿主的 `UIPage` 容器树 + 元素/整页画布（`Ui.canvas` / `Ui.fillCanvas`），不需要 Compose 编译器，见第十节。
- 按钮型插件最简单：三个插槽的 `onClick` 是普通 lambda，注册设置行/卡片/页面底部按钮都能用，点了弹 toast、读只读数据都没问题。
- 最小样例在 `docs/external-sample/`：`HelloPlugin.java` 是按钮型（`build-sample.ps1`），`PagePlugin.java` 是页面型（`build-sample-page.ps1`）。两个脚本都是完整流水线（javac 编 → jar → `d8 --release --min-api 26` 转 dex → 写 plugin.json → 打 zip）；换掉脚本里的 javac/d8/android.jar 路径就能编你自己的。
- d8 需要 `--lib android.jar`，否则会抱怨找不到 Android 类；`--lib` 也可以直接指宿主 apk。

页面型插件的全部写法（Java，照抄可跑）：

```java
SimplePage page = new SimplePage(manifest.getId() + ":main", "我的页面")
    .sub("副标题")                                         // 可选
    .onAction(actionId -> {                                 // SimpleAction 是普通 void 方法
        if ("inc".equals(actionId)) {
            // 改 kv、host.toast(...)，然后 host.invalidate() 让宿主重画
        }
    })
    .render(p -> {                                          // 4.1.22 起：每次重画都重跑，行取最新数据
        int clicks = host.getData().kv().getInt("clicks", 0);
        p.section("主指标");                                    // 0.2 起：整套官方 UI
        p.hero("计数", String.valueOf(clicks), "点下面加一");
        p.progress("今日进度", clicks, 10);
        p.stat("全部笔记", String.valueOf(notes.size()));      // 只读统计行
        p.stepper("杯数", 3, 0, 20, 1, "cups");                 // 点 ＋ 收到 "cups:+1"
        p.button("＋", "计数加一", "共 " + clicks + " 次", "inc"); // 第 4 参是 actionId
    });
host.getPages().add(page);
// 可选：再给一个设置页入口（管理页「插件页面」也能直接点进来）
host.getButtons().add(new ButtonSpec(manifest.getId() + ":entry", ButtonSlot.SETTINGS_ROW,
    "▤", "我的页面",
    () -> { host.openPage(manifest.getId() + ":main"); return kotlin.Unit.INSTANCE; }, null));
```

- `SimplePage` 支持上面「官方 UI 行」那 18 种（4.1.27 起 17 种，4.1.30 加 shape）；要长列表（几十上百条、需要懒加载）仍然要拆成多个页面，或者把插件打进宿主用 `ListPageSpec`。
- 统计行/按钮行如果是在 `install()` 里一次性算好的，装上之后数据再变页面也不会变——4.1.22 之前示例页面就是这样（toast 数到 10、页面还是 0）。要动态就改用 `render(p -> ...)`，并在数据变化后调 `host.invalidate()`；renderer 里只读数据、只写行，别 toast / 改数据 / 开页面（会被重画重复触发）。

怎么装进手表（4.1.15 起四种，前两种不用电脑）：

1. 管理页「＋ 安装示例插件」：装 assets 里内置的 `hello.wplugin`，用来验证整条链路（装完设置页会多出「★ 示例外置插件」一行）。
2. 管理页「⇩ 从文件夹安装」：把 `.wplugin` 用 adb 推到 `/sdcard/Android/data/com.ioo.watchnote/files/plugins-inbox/`，再点这一行，会逐个装。
3. 系统文件选择器（手表上点开 .wplugin 文件直接装）：4.1.13 起已支持，选完文件先预览再确认。
   不是每块手表都装了系统文件选择器；起不来 App 会提示「这台手表没有文件选择器，用「从文件夹安装」」，不会闪退。
4. 「⇅ 手机传 / 网址安装」（4.1.15 起）：手机和手表连同一个 Wi-Fi，手表上这页会显示 `http://192.168.x.x:894x`；手机浏览器打开后，既能选文件上传，也能粘贴一个指向 `.wplugin` 的直链让手表自己下载（4 MB 上限，只收 http/https）。收到的包一样先弹清单再装。

4.1.11 起，三个入口都会先弹一张清单确认（名字 / 版本 / 作者 / 权限 / 包大小 / `SHA-256` 前 12 位 / 首装还是升级），
点「安装」才真正解压；同一个 id 的新包版本低于已装版本会被直接拒绝（插件数据按 id 存，降级容易把数据读坏）。

作者签名（可选，4.1.14 起）：

- 不签名也能装（第一次装没有分发中心背书，信任来自你自己选的包）。
- 但一旦装过签名版：以后升级必须带**同一把钥匙**的签名——换钥匙的包、没签名的包都会被拒。
- 签名只证明「包没被改、作者钥匙没换」，不证明作者人品；要给别人用还是走可信渠道。
- 打一次签名（在 `WristNote-v5` 目录下）：

```powershell
# 第一次：生成钥匙并签
pwsh -File docs\external-sample\sign-sample.ps1 -Package 你的插件.wplugin -NewKey

# 以后：用同一个 keys\plugin-private.pem 继续签
pwsh -File docs\external-sample\sign-sample.ps1 -Package 你的插件.wplugin
```

- 脚本会：把公钥写进包内 `plugin.json` 的 `publicKey`、加 `signingAlgorithm`、算出签名原文、用 ECDSA P-256 签出 `plugin.sig`、整包重写；最后打印公钥指纹。
- 私钥在包旁边的 `keys\plugin-private.pem`，**别外传、别提交仓库**；公钥备份是 `keys\plugin-private.public.spki.b64`。
- 脚本和宿主用同一套规则：zip 里的目录条目（如 `assets/`）不算文件、路径反斜杠归一化为 `/`、清单按路径的 UTF-8 字节序排序，所以中文/emoji 文件名也不会签歪（已做过 PowerShell 签、Node 独立验的跨语言对照）。
- 想先看签名长什么样：`docs/external-sample/hello-signed.wplugin` 是签好的示例包（指纹 `E1B6E3610EE9F811`），装它预览里会显示「已签名 · E1B6E3610EE9F811」；示例私钥不随仓库提供。
- 装的时候预览会多两行：「包指纹」和「签名：已签名 · 指纹」；外置插件详情页也有「签名」一行，和脚本打印的指纹对得上就说明是同一把钥匙。
- 签名格式细节（原文怎么拼、公钥放哪）见 `插件外置化-v2设计.md` 的「签名格式 v1」。

装完在哪看：

- 「设置 → 插件」列表底部「外置插件 N 个」，每个外置插件是 `◈` 一行（`vN · 使用中/未运行`）。
- 点进详情：版本、作者、`SHA-256` 前 16 位、安装时间、注册的页面和按钮、两步确认卸载。卸载会连代码带这个插件自己的 kv 一起清。
- 外置插件和内置插件共用同一套 `PluginCore`：页面/按钮上限、权限检查、崩溃隔离、开关语义完全一样。

安全边界（v2.0）：

- 外置插件和宿主同进程，不能写笔记；网络只能走宿主那一条渠道 `host.net()`（0.4.5 起，需在清单声明 `net` 权限，用户可在设置里单独关）；拿不到 Activity、拿不到宿主导航栈。
- 宿主在解压前先验包（结构/路径/大小/必备文件），验不过就一个字节都不写盘；装失败不影响腕记本身。
- 安装记录里留 SHA-256 和签名公钥指纹，管理页能对上「我装的是不是那个包」；4.1.14 起支持可选作者签名，签名版不能被换钥匙或未签名包覆盖。

还没支持（别踩空）：

- 插件商店 / 分发中心：还没有集中分发；但 4.1.15 起不用数据线——把 `.wplugin` 放到任意可下载的网址，在手表「手机传 / 网址安装」里填直链，或手机浏览器打开手表的接收页上传即可。
- 导出备份：没有（插件代码和 kv 目前要重装才能重建）。
- 证书链 / 作者身份认证：没有；签名只有自签公钥指纹，没有第三方背书。
- assets 注入宿主资源表：没有；`assets/` 只做保留，图标之类暂时自己用代码画。

## 九、前置模块：给别的插件提供 API（0.3，4.1.29 起）

如果你写了一套东西，觉得别的插件也会用（官方组件的组合封装、时间/字数算法、解析器…），
可以单独打一个 **lib 型插件**：它不占界面，只对外提供类；别人声明依赖后直接调。

`plugin.json` 少的写法（前置包）：

```json
{
  "schemaVersion": 1,
  "id": "com.example.uikit",
  "name": "示例前置",
  "version": 1,
  "minApi": 3,
  "kind": "lib",
  "provides": ["com.example.uikit.FrontKit"],
  "entryClass": "com.example.uikit.FrontKitPlugin",
  "author": "你的名字",
  "description": "给别的插件用的 UI / 算法工具"
}
```

依赖方的 `plugin.json` 加一行：

```json
  "requires": ["com.example.uikit>=1"]
```

（也可以只写 `"com.example.uikit"`，等同于 `>=1`；最多 8 个依赖。）

规则：

- **lib 不能有页面和按钮**。安装时一旦注册了页面/按钮，宿主判「前置模块不能注册页面或按钮」并回滚。
- **先问再用**：`host.getLibraries().available("com.example.uikit", "com.example.uikit.FrontKit")`，
  为 false 时自己降级。示例 `FrontUiPlugin` 在不可用时退回官方组件，`FrontAlgoPlugin` 退回简单写法。
- **同名不连坐**：前置提供的类名如果和官方重名，宿主只把**那个符号**标成 blocked（`blocked(id)` 能拿到清单），
  其余符号照常可用；不要因为一个重名就以为整包废了。
- **缺前置只是依赖者装不上**：前置没装或版本低于 `>=N`，装依赖者会直接被拒并写明缺谁；前置本身不受影响。
- **卸载有保护**：还有插件依赖它时卸载会被拒，管理页会列出「谁在用它」。
- **实现在哪**：`plugin/PluginLibraries.kt`；示例源码 `docs/external-sample/FrontKit.java`、`FrontUiPlugin.java`、
  `FrontAlgoPlugin.java`，打包脚本 `build-front-samples.ps1`。
- 前置的 dex 会被拼进依赖者的 DexClassLoader（最多 4 层），所以直接 `FrontKit.fmtMins(mins)` 就能用，
  不需要在插件里再打一份。

装法：先装前置包（`uikit.wplugin`），再装依赖它的插件（`frontui.wplugin` / `frontalgo.wplugin`）；
反过来装，第二个就会被拒并提示缺前置。


## 十、0.4.5：布局容器 / 画布 / 联网 / 插件主页面（4.1.34 起）

> `API_LEVEL` 5、`MODULE_VERSION` 0.4.5。这一版把两件事一起交给插件：**界面怎么排**（容器树）和**能不能自己画**（画布）。
> 老的 `SimplePage` 18 行照旧能用，两种页面可以同时注册（各自算 1 页）。Java 写的插件同样能用 —— 下面的工厂方法全是 `@JvmStatic`。

### 1. 声明式新页面 `UIPage`：一棵容器树

```kotlin
val page = UIPage("com.example.mine:home", "我的主页")
    .sub("一行副标题")
    .asMainPage()          // 可选：声明成插件主页面，占指示栏第 6 格

page.add(
    Ui.group("今天") {
        Ui.stat("喝水", "3 / 8 杯")
        Ui.progress("步数", 6400, 10000, "64%")
    },
    Ui.row(8) {                       // 横排，间距 8dp
        Ui.canvas(56, DrawBlock { pen ->     // 元素画布：跟官方行同层
            pen.circle(0.5f, 0.5f, 0.42f, "primary", strokeDp = 6f)
            pen.text("42", 0.5f, 0.5f, sizeDp = 16f, bold = true)
        }).weight(1f)
        Ui.button("＋1", "add")
    },
    Ui.note("下面这行是官方行，上面是画布，中间没有开关"),
)

page.onAction { actionId ->        // 所有官方行 / 画布命中区都回这里
    when (actionId) {
        "add" -> { /* 改数据 */ host.invalidate() }
    }
}
host.pages.add(page)              // 注册（页面 id 必须用插件 id + 冒号开头，每插件最多 3 页）
```

容器工厂：

| 工厂 | 作用 |
| --- | --- |
| `Ui.column(spacingDp)` | 竖排，默认就是它（自动从上往下） |
| `Ui.row(spacingDp)` | 横排，子节点按权重分宽 |
| `Ui.box(...)` | 叠放，子节点压在彼此上面，用 `align` 定位 |
| `Ui.group(title)` | 圆角卡片分组，里面继续排 |
| `Ui.grid(cols)` | 等宽网格，每行 cols 个 |
| `Ui.scroll(...)` | 自己滚（一般不用，整页已经能滚） |
| `Ui.spacer(dp)` / `Ui.divider()` | 空白 / 分割线 |

链式配置（每个节点都能调）：`weight(f)`、`height(dp)`、`pad(dp)`、`spacing(dp)`、`columns(n)`、`align(0~8)`、`action(id)`。

官方行工厂（18 种，跟 `SimplePage` 一一对应）：
`section / note / stat / hero / button / item / progress / ring / stepper / chips / colorCard / timeCard / toggle / empty / bars / shape / divider / space`。

**两种排布怎么并存**（这是 0.4.5 的关键）：

- **自动**：容器的 `children` 顺序就是渲染顺序，从上往下 / 从左往右，不用算坐标。
- **第几个**：节点在容器里的下标就是它的序号；容器自己也能是别的容器的第 N 个（嵌套）。
- **属于哪个**：节点挂在哪个容器里，它就属于哪个容器 —— 这就是「归属」，改归属就是 `add` 到另一个容器。
- **要固定位置**：用 `Ui.row` + `weight` 分格，或用 `Ui.spacer` / `Ui.box` + `align` 占位；不需要写像素坐标。
- **同一页混排**：官方行、画布、第三方插件组件放在同一个 `children` 列表里，按同一个顺序排，没有优先级差异。

### 2. 画布：两级，一套画笔

| 形态 | 写法 | 用在哪 |
| --- | --- | --- |
| 元素画布 | `Ui.canvas(heightDp = 56) { pen -> ... }` | 页面里一块自绘区域：环形图、仪表盘、自定义按钮 |
| 整页画布 | `Ui.fillCanvas { pen -> ... }` + `page.fullPage()` | 整页自己画：表盘、全屏读数，连标题都不要 |

画笔 `Pen`（坐标一律归一化 0~1，粗细 / 字号按 dp）：

```kotlin
pen.clear(colorHex = "card")
pen.rect(x, y, w, h, colorHex = "primary", radius = 0.2f, strokeDp = 0f)
pen.circle(cx, cy, r, colorHex = "primary", strokeDp = 0f)
pen.line(x1, y1, x2, y2, colorHex = "muted", widthDp = 1.5f)
pen.arc(cx, cy, r, startDeg, sweepDeg, colorHex = "primary", strokeDp = 6f, fromCenter = false)
```

```kotlin

    if (r.ok) host.toast(r.body.take(80)) else host.toast(r.error ?: "失败")
```

`HttpResult`：`code`（HTTP 状态码，失败为 -1）、`body`（文本，最多 256KB）、`error`（`no_permission / blocked / bad_url / too_frequent / timeout / dns / offline / too_large / unknown`）、`ok`。

宿主的护栏（0.4.5 定死）：只允许 http/https；拒本机与内网（localhost / 127. / 10. / 192.168. / 172.16-31. / 169.254. / .local / IPv6）；响应 ≤ 256KB；超时夹在 5~30 秒（默认 10 秒）；每个插件 30 次/分；同时最多 2 个请求；离开页面就取消；UA 带宿主版本和插件 id。

**诚实说明**：外置插件是普通 Java 字节码，技术上拦不住它自己开 socket。所谓「唯一渠道」靠的是：只提供这一条 API、安装时把「要联网」写在清单上、请求进日志、上架审核 —— 不是沙箱。

### 4. 插件主页面与指示栏第 6 格

- 一个插件最多 1 个主页面：`page.asMainPage()`。
- 全局只有 1 个插件主页时：指示栏变成 6 格，第 6 格就是那一页（跟官方页一样能左右滑到）。
- 全局有 2 个以上时：第 6 格是「插件页面」抽屉，列出全部插件主页，点一行进去，返回回抽屉。
- 一个都没有时：指示栏还是 5 格（0.4.5 之前的样子）。
- 卸载 / 停用插件 → 主页自动消失，指示栏退回 5 格，不会留空页。

### 5. 画布和 API 混用的三条规矩

1. 没有 `mode` 开关。画布只是元素之一，官方行 / 容器 / 画布 / 第三方组件同层。
2. API 到处能调：宿主 API（笔记 / 待办 / 课程表 / 联网）和第三方插件 API 在页面任何位置可用，包括 `onDraw` 回调里。`onDraw` 不阻塞，发请求后下一帧 `host.invalidate()` 再画。
3. 想全自绘就 `fillCanvas + fullPage()`，不拦也不降级；想省事就全用官方行。两种都不限制。

### 7. 这一版故意没做的

插件改**腕记自己的官方页面**（布置、按钮样式）没做。那需要官方页面结构可注入 + 多插件冲突仲裁 + 一键回退，是 0.5 的验收线。
所以这一版叫 0.4.5，不叫 0.5 —— App 里「关于 → 详细信息」和插件页底部都写了这句话。

### 8. 4.1.35 修的三处（写插件要知道）

1. **`Ui.timeCard` / `SimplePage.timeCard` 收两种写法**：老写法是毫秒时间戳（`timeCard(9 * 3600_000L, ...)`），新写法直接收 `"09:30"` / `"09:30:00"`，宿主按当天时钟换算，越界（小时 >23、分钟 >59）显示 00:00。传纯数字仍然按毫秒算，老包不用改。
2. **整页页有返回键了**：`fullPage()` 的页面以前只盖一层 `Box`、连返回都不画，只能靠系统手势退出。4.1.35 起宿主在左上角叠一颗 34dp 圆底「←」；`asMainPage()` 的主页面不画（那一页靠指示栏左右滑走）。
3. **普通页里的 `Ui.scroll()` 不再嵌套滚动**：普通页内容本身在官方 `SubPageFrame` 的可滚动容器里，再套一层 `verticalScroll` 会撞上「measured with infinity maximum height」，直接崩。现在宿主对普通页传 `allowScroll = false`，`scroll` 退化成普通 `column`（内容照样能滚，靠外层）；只有 `fullPage()` 页面里的 `scroll` 才是真内嵌滚动。想在自己的区域里滚，用 `fullPage`。
